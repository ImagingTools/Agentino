## 1. Что такое Agentino

**Agentino** — система централизованного управления сервисами (программами,
приложениями, серверными процессами), работающими на множестве компьютеров
в сети.

На каждом управляемом компьютере устанавливается небольшая программа —
**агент** (AgentinoAgent). Агент запускает, останавливает и контролирует
сервисы на своей машине. Все агенты подключаются к **центральному серверу**
(AgentinoServer), через который оператор из одного окна (или из браузера)
видит состояние всей инфраструктуры и управляет ею.

Проще говоря, Agentino позволяет:

* видеть, какие программы запущены на каких компьютерах;
* запускать и останавливать их удалённо;
* настраивать их параметры и связи между ними;
* смотреть их журналы;
* при необходимости — работать в командной строке удалённой машины,

не подключаясь к каждому компьютеру по отдельности.

## 2. Какие задачи решает Agentino

| Задача | Как это делается в Agentino |
|--------|-----------------------------|
| Централизованный контроль парка машин | Страница **Agents** показывает все агенты и их состояние подключения в реальном времени |
| Безопасное подключение новых машин | Новый агент попадает в статус **Pending** и начинает работать только после одобрения оператором (**Approve**) |
| Удалённый запуск/остановка программ | Команды **Start** / **Stop** в списке сервисов, в топологии или в редакторе сервиса |
| Регистрация новой программы на машине | Команда **New** — создание сервиса: путь к исполняемому файлу, аргументы, параметры |
| Автозапуск программ при старте машины | Опция **Autostart** в настройках сервиса |
| Нестандартный запуск/остановка | Пользовательские скрипты запуска и остановки (**Start script** / **Stop script**) |
| Настройка связей между сервисами | Раздел **Connections**: входящие подключения, внешние порты и выбор поставщика для исходящих подключений |
| Наглядное представление инфраструктуры | Страница **Topology** — схема всех сервисов и связей между ними |
| Диагностика | Журналы агента (**Agent Log**) и сервисов (**Service Log**), уровень трассировки |
| Администрирование работающего сервиса | Страница **Administration** в редакторе сервиса (для сервисов, поддерживающих её) |
| Работа в консоли удалённой машины | Страница **Terminal** в редакторе агента — полноценный удалённый терминал |
| Временное отключение или отзыв машины | Команды **Suspend** / **Resume** / **Revoke** для агентов |

## 3. Основные понятия

* **Сервер Agentino (AgentinoServer)** — центральный узел. Хранит список
  агентов, собирает сведения об их сервисах, предоставляет интерфейс
  оператора и API.
* **Агент (AgentinoAgent)** — программа, установленная на управляемом
  компьютере (обычно как системная служба). Является «хозяином» своих
  сервисов: хранит их описание, запускает и останавливает их, следит за их
  состоянием. Агент продолжает управлять своими сервисами, даже если связь
  с сервером временно потеряна.
* **Сервис** — программа (исполняемый файл), зарегистрированная на
  конкретном агенте. Для сервиса задаются путь, аргументы командной строки,
  параметры запуска, журналирования и связей.
* **Подключение (Connection)** — описание сетевого взаимодействия сервиса:
  * *входящее* (input) — адрес/порты, на которых сервис принимает запросы;
  * *исходящее* (output) — сервис, к которому данный сервис должен
    подключиться (например, к базе данных или к другому серверу).
* **Топология** — схема всех сервисов всех агентов и связей между ними.
* **Регистрация агента (Enrollment)** — процедура допуска нового агента
  к серверу. Агент предъявляет свой уникальный идентификатор, а оператор
  одобряет или отклоняет его.

## 4. Состав системы и способы доступа

| Компонент | Где работает | Назначение |
|-----------|--------------|------------|
| **AgentinoServer** | Центральный сервер | Хранит данные, принимает подключения агентов и операторов |
| **AgentinoAgent** | Каждый управляемый компьютер | Управляет сервисами своей машины |
| **AgentinoClient** | Рабочее место оператора | Настольный графический клиент для работы с сервером (или напрямую с агентом) |
| **Веб-интерфейс** | Браузер оператора | Тот же интерфейс, что и в клиенте, доступный через браузер |

Сетевые порты по умолчанию:

| Сторона | HTTP | WebSocket |
|---------|------|-----------|
| Сервер Agentino | 7111 | 7112 |
| Агент (локальный интерфейс) | 7222 | 7223 |

> Фактические порты могут быть изменены администратором при установке.
> Уточните адрес и порты у администратора вашей системы.

## 5. Первый запуск: быстрый старт

Ниже — минимальная последовательность действий, чтобы начать управлять
сервисами на одной удалённой машине.

1. **Установите и запустите сервер Agentino** (выполняет администратор).
2. **Установите агент на управляемый компьютер.** На Windows используется
   установщик *AgentinoAgent*; агент регистрируется как системная служба
   и запускается автоматически.
3. **Укажите агенту адрес сервера.** Откройте локальный интерфейс агента
   (см. [раздел 13](#13-локальный-интерфейс-агента)), введите адрес сервера
   в поле **Agentino URL** и нажмите **Connect**.
4. **Одобрите агента на сервере.** Войдите в интерфейс сервера, откройте
   страницу **Agents**, выберите фильтр **Pending**, выделите новый агент
   и нажмите **Approve**. (Самый первый агент может быть одобрен
   автоматически.)
5. **Добавьте сервис.** На странице **Topology** нажмите **New**, выберите
   целевой агент, заполните имя и путь к исполняемому файлу, сохраните.
6. **Запустите сервис** командой **Start** и убедитесь, что его статус
   сменился на **Running**.

Подробности по каждому шагу приведены в разделах ниже.

## 6. Вход в систему и права доступа

При открытии интерфейса может потребоваться ввести логин и пароль
(в зависимости от настроенного режима управления пользователями). Панель
текущего пользователя отображается в правом верхнем углу окна.

Набор доступных страниц и команд зависит от прав вашей учётной записи.
Если какая-то кнопка неактивна или страница отсутствует, скорее всего,
у вас нет соответствующего права — обратитесь к администратору.

| Группа | Права |
|--------|-------|
| Управление агентами | View Agents, Add Agent, Edit/Change Agent, Remove Agent, Approve Agents |
| Управление сервисами | View Services, Add Service, Edit/Change Service, Remove Service, Start Service, Stop Service |
| Топология | View Topology |
| Удалённый терминал | RemoteTerminal (выдаётся только доверенным операторам) |

## 7. Интерфейс сервера Agentino

Главное окно состоит из:

* **Левой панели навигации** со страницами:
  * **Topology** — схема всех сервисов;
  * **Agents** — список агентов.
* **Панели команд** (тулбара) над рабочей областью: New, Edit, Remove,
  Start, Stop, Approve и т. д. Набор команд зависит от страницы, а доступность
  — от выбранного элемента и его состояния.
* **Рабочей области с вкладками.** Открытые агенты и сервисы открываются
  в отдельных вкладках, поэтому можно одновременно работать с несколькими
  объектами.

## 8. Работа с агентами

### 8.1. Список агентов

Страница **Agents** показывает все агенты, известные серверу, независимо от
их статуса регистрации. Над таблицей расположен фильтр по статусам с
количеством агентов в каждом:

**All**, **Pending**, **Approved**, **Suspended**, **Rejected**, **Revoked**.

В колонке статуса для одобренного агента отображается состояние связи
(**Connected** / **Disconnected**), для остальных — статус регистрации.

### 8.2. Регистрация (одобрение) агентов

Каждый новый агент при первом подключении получает статус **Pending**
(ожидает решения). Пока агент не одобрен, управлять им нельзя.

Выделите агента в списке и используйте команды тулбара:

| Команда | Когда доступна | Результат |
|---------|----------------|-----------|
| **Approve** | Статус Pending | Агент допущен к работе |
| **Reject** | Статус Pending | Агент отклонён |
| **Suspend** | Статус Approved | Работа агента временно приостановлена |
| **Resume** | Статус Suspended | Работа агента возобновлена |
| **Revoke** | Approved или Suspended | Допуск агента отозван |
| **Reset** | Rejected или Revoked | Решение сброшено, агент может зарегистрироваться заново |

> Одобряйте только те агенты, которые вы ожидаете увидеть. Неизвестный агент
> в статусе Pending — повод проверить, кто и откуда его подключил.

### 8.3. Редактор агента

Двойной щелчок по одобренному агенту (или команда **Edit**) открывает
редактор агента в отдельной вкладке. Редактор содержит страницы:

* **General** — имя и описание агента, режим подробных сообщений
  (**Verbose message**) и уровень трассировки (**Tracing level**);
* **Services** — список сервисов этого агента (в заголовке страницы
  отображается их количество);
* **Agent Log** — журнал агента (точка рядом с названием означает, что
  появились новые записи);
* **Terminal** — удалённый терминал (только при наличии права
  RemoteTerminal, см. [раздел 12](#12-удалённый-терминал)).

Для сохранения изменений используйте команду сохранения на тулбаре
редактора.

### 8.4. Удаление агента

Выделите агент и выполните **Remove**, затем подтвердите удаление в диалоге.

## 9. Работа с сервисами

Работать с сервисами можно из трёх мест:

* страница **Services** в редакторе агента — список сервисов конкретной машины;
* страница **Topology** — все сервисы на одной схеме;
* локальный интерфейс агента.

### 9.1. Создание сервиса

1. На странице **Topology** нажмите **New** (или **New** на странице
   **Services** редактора агента).
2. На сервере появится диалог **Select target agent** — выберите агент, на
   котором будет работать сервис, и нажмите **Select**.
3. Откроется редактор нового сервиса. Заполните как минимум **Name** и
   **Path** и сохраните сервис.

### 9.2. Редактор сервиса

Редактор открывается двойным щелчком по сервису, командой **Edit** или
клавишей **Enter** на выбранном элементе топологии. В верхней части
отображается текущий статус сервиса (Running, Stopped, Starting, Stopping,
Unknown или *Not saved yet* для несохранённого сервиса).

#### General → Information

| Поле | Описание |
|------|----------|
| **Name** | Имя сервиса; используется в списках, топологии и заголовках вкладок. Обязательно |
| **Description** | Описание назначения сервиса |
| **Path** | Путь к исполняемому файлу на машине агента. По нему сервис запускается и определяется его работающий процесс. Обязательно. Кнопка обзора позволяет выбрать файл в файловой системе агента |
| **Arguments** | Аргументы командной строки, передаваемые исполняемому файлу |

#### General → Options

| Поле | Описание |
|------|----------|
| **Autostart** | Автоматически запускать сервис при старте агента |
| **Verbose Message** | Включить диагностические (трассировочные) сообщения сервиса |
| **Tracing level** | Объём выводимой диагностической информации |
| **Start script** / **Start Script Path** | Использовать для запуска сервиса указанный скрипт вместо прямого запуска исполняемого файла |
| **Stop script** / **Stop Script Path** | Использовать для остановки сервиса указанный скрипт |

#### Connections → Server (входящие подключения)

После сохранения сервиса Agentino автоматически загружает из него сведения
о поддерживаемых подключениях (статус *Plugin loaded*). Если загрузка не
удалась, проверьте путь к исполняемому файлу и нажмите **Reload**.

Для каждого входящего подключения можно нажать **Edit** у пункта
**Extern Connections** и в диалоге **Edit ports** задать внешне доступные
адреса: **Host**, **Http Port**, **Web Socket Port**, **Http Path**,
**Security**.

#### Connections → Output Connections (исходящие подключения)

Здесь указывается, к каким другим сервисам должен подключаться данный
сервис. Для каждого подключения показаны **Service Type** (требуемый тип
сервиса) и **Connection Name**. В списке **Available Connections** выберите
подходящий сервис-поставщик — он может работать на любом агенте.

Если подходящих поставщиков нет, будет показано сообщение о том, что
нужно сначала добавить сервис требуемого типа на любой агент (запускать
его для этого не обязательно).

#### Administration

Появляется для сервисов, которые поддерживают собственное
администрирование. Позволяет управлять внутренними настройками работающего
сервиса. Если сервис не запущен, отображается сообщение
*Service not running*.

#### Service Log

Журнал выбранного сервиса (доступен после сохранения сервиса), см.
[раздел 11](#11-журналы-логи).

### 9.3. Запуск и остановка

* **Start** — доступна, когда сервис остановлен (Stopped).
* **Stop** — доступна, когда сервис работает (Running).

Во время операции отображается индикатор *Starting service...* /
*Stopping service...*. Если в редакторе есть несохранённые изменения, при
запуске будет предложено сохранить их (*This service has unsaved changes.
Save and start it?*).

Если агент отключён, статус сервиса неизвестен и команды запуска/остановки
недоступны.

### 9.4. Удаление сервиса

Выделите сервис и выполните **Remove**, затем подтвердите удаление.
Удалить сервис можно только когда его агент подключён — иначе появится
сообщение *Cannot delete the service while the agent is disconnected*.

## 10. Топология

Страница **Topology** отображает все сервисы в виде схемы: каждый сервис —
отдельный блок, связи между сервисами — линии между блоками.

Возможности:

* **Выбор сервиса** щелчком мыши — справа откроется панель с подробной
  информацией о нём (в том числе внешние адреса подключений).
* **Перемещение блоков** мышью — расположение сохраняется автоматически.
* **AutoFit** — автоматически вписать схему в окно.
* **New / Edit / Remove / Start / Stop** — те же действия, что и в списке
  сервисов. **Enter** открывает редактор выбранного сервиса, **Delete** —
  удаляет его (с подтверждением).
* **Обновление в реальном времени** — статусы сервисов и изменения состава
  обновляются без перезагрузки страницы.

Сервисы отключённых агентов остаются на схеме с последним известным
состоянием и помечаются значками предупреждения; управлять ими до
восстановления связи нельзя.

> Расположение блоков на схеме сервера и на схеме в локальном интерфейсе
> агента хранится независимо.

## 11. Журналы (логи)

* **Agent Log** (редактор агента) — сообщения самого агента.
* **Service Log** (редактор сервиса) — сообщения выбранного сервиса.

Журналы обновляются автоматически. Чтобы получить больше диагностической
информации, включите **Verbose message** и увеличьте **Tracing level**
в настройках агента или сервиса.

## 12. Удалённый терминал

Удалённый терминал позволяет работать в командной строке компьютера, на
котором установлен агент, прямо из интерфейса Agentino — так же, как в
обычном окне терминала.

> ⚠️ Терминал даёт полный доступ к выполнению команд на удалённой машине
> с правами службы агента. Доступ к нему имеют только пользователи
> с правом **RemoteTerminal**.

### Как открыть

1. На странице **Agents** откройте одобренный агент (двойной щелчок или
   **Edit**).
2. Перейдите на страницу **Terminal**.
3. Нажмите **+** (или **Ctrl+Shift+T**) — откроется новая вкладка с
   оболочкой по умолчанию (Command Prompt на Windows, Bash на Linux).
   Кнопка **▾** позволяет выбрать другую оболочку (например, PowerShell
   или sh) — предлагаются только оболочки, реально доступные на агенте.

### Работа в терминале

| Действие | Как выполнить |
|----------|---------------|
| Выполнить команду | Щёлкнуть по области вывода, ввести команду сразу после приглашения и нажать **Enter** |
| История команд | Клавиши **↑ / ↓** (обеспечивается оболочкой) |
| Вставить текст | **Ctrl+V** или **Shift+Insert** |
| Прервать текущую команду | **Ctrl+C** (сессия при этом не закрывается; при выделенном тексте — копирование) |
| Очистить экран | **Clear** |
| Скопировать весь вывод | Кнопка копирования в буфер обмена |
| Сохранить вывод в файл | **Save terminal log** (текстовый файл) |
| Закрыть сессию | Кнопка закрытия вкладки |
| Восстановить потерянный канал вывода | **Reconnect** |

Поддерживаются цветной вывод и полноэкранные программы (например, `vim`,
`mc`, `top`).

### Ограничения

* Можно открыть несколько вкладок, но число одновременных сессий на агенте
  ограничено.
* Неактивная сессия автоматически закрывается примерно через **15 минут**;
  примерно за минуту до закрытия выводится предупреждение.
* Сессии привязаны к вкладке редактора агента и закрываются вместе с ней.
* Команды выполняются с правами службы агента, без повышения привилегий.

## 13. Локальный интерфейс агента

У каждого агента есть собственный интерфейс (по умолчанию —
`http://<адрес-агента>:7222`). Он полезен для первоначальной настройки и
для работы с машиной, когда центральный сервер недоступен.

Страницы локального интерфейса:

* **Settings** — подключение к серверу:
  * **Status** — текущее состояние связи с сервером: *Connected*
    (зелёный), *Disconnected* (красный), *Unknown* (жёлтый),
    *Checking the connection*;
  * **Agentino URL** — адрес сервера Agentino; после ввода нажмите
    **Connect**.
* **Topology** — схема и управление сервисами этого агента (создание,
  редактирование, запуск, остановка, удаление) без выбора целевого агента.

## 14. Типовые сценарии

### Подключить новый компьютер

1. Установить AgentinoAgent на компьютер.
2. В локальном интерфейсе агента указать **Agentino URL** и нажать
   **Connect**.
3. На сервере: **Agents** → фильтр **Pending** → выбрать агент → **Approve**.
4. Убедиться, что статус агента — **Connected**.

### Развернуть и запустить приложение на удалённой машине

1. Скопировать приложение на машину агента (например, через средства
   администрирования или терминал).
2. **Topology** → **New** → выбрать агент → указать **Name**, **Path**,
   при необходимости **Arguments**.
3. Включить **Autostart**, если приложение должно запускаться вместе
   с агентом.
4. Сохранить и нажать **Start**.

### Связать два сервиса

1. Убедиться, что сервис-поставщик (например, база данных) уже добавлен.
2. Открыть сервис-потребитель → **Connections → Output Connections**.
3. В **Available Connections** выбрать сервис-поставщик и сохранить.
4. Связь появится на схеме **Topology**.

### Разобраться, почему сервис не работает

1. Найти сервис на **Topology** и проверить его статус и статус агента.
2. Открыть **Service Log**; при необходимости включить **Verbose Message**
   и повысить **Tracing level**, перезапустить сервис.
3. Проверить **Agent Log** у соответствующего агента.
4. При необходимости открыть **Terminal** и проверить окружение (наличие
   файлов, занятость портов и т. п.).

### Временно вывести машину из работы

* **Suspend** — временно приостановить, **Resume** — вернуть.
* **Revoke** — окончательно отозвать допуск (вернуть можно через
  **Reset** и повторное одобрение).

## 15. Решение проблем

| Симптом | Возможная причина и решение |
|---------|-----------------------------|
| Новый агент не появляется в списке | Проверьте **Agentino URL** в локальном интерфейсе агента, сетевую доступность сервера и порты (по умолчанию 7111/7112) |
| Агент в статусе Pending | Агент ожидает одобрения — выполните **Approve** |
| Нельзя открыть агента (Edit неактивна) | Агент ещё не одобрен, приостановлен или отклонён |
| Агент в статусе Disconnected | Служба агента остановлена или нет сетевой связи с сервером |
| Start/Stop неактивны | Агент отключён (статус сервиса неизвестен) или у вас нет прав |
| *Cannot delete the service while the agent is disconnected* | Восстановите связь с агентом и повторите удаление |
| *Failed to load plugin* | Неверный **Path** или файл недоступен на машине агента — исправьте путь и нажмите **Reload** |
| Нет подходящих **Available Connections** | Сервис требуемого типа ещё не добавлен ни на один агент |
| Нет страницы **Terminal** | Нет права RemoteTerminal или агент не одобрен |
| *No shell available* | Агент не нашёл ни одной поддерживаемой оболочки |
| *Output subscription lost* в терминале | Нажмите **Reconnect** или откройте новую сессию |
| *[session closed: idle timeout]* | Сессия закрыта из-за бездействия — откройте новую вкладку |

## 16. Справочник статусов

### Статусы регистрации агента

| Статус | Значение |
|--------|----------|
| **Pending** | Ожидает решения оператора |
| **Approved** | Допущен к работе |
| **Suspended** | Временно приостановлен |
| **Rejected** | Отклонён |
| **Revoked** | Допуск отозван |

### Статусы связи агента (для одобренных агентов)

| Статус | Значение |
|--------|----------|
| **Connected** | Агент на связи |
| **Disconnected** | Связь с агентом отсутствует |
| **Undefined / Unknown** | Состояние ещё не определено |

### Статусы сервиса

| Статус | Значение |
|--------|----------|
| **Running** | Сервис работает |
| **Stopped** | Сервис остановлен |
| **Starting** | Выполняется запуск |
| **Stopping** | Выполняется остановка |
| **Unknown** | Состояние неизвестно (обычно агент отключён) |
| **Not saved yet** | Сервис создан, но ещё не сохранён |
